# ENOSH-SDL v0.3 — Semantic Decision Layer (prototype)

**مشروع محاكاة محلي قابل للتشغيل على Windows، ولا يحتاج اشتراكًا أو مفتاح API.**

الإصدار الحالي **محرك قرار تجريبي Dry Run** وليس نظامًا قادرًا على إدراك الصوت الخام أو الصور الخام أو تشغيل روبوت فعلي. يستقبل مدخلات متعددة الوسائط **بعد** استخراجها بواسطة أنظمة الإدراك: نص، تفريغ الكلام إلى نص (ASR)، تسميات الأشياء في المشهد (vision labels)، وحساسات رقمية. الوضع الافتراضي يستخدم قواعد كلمات مفتاحية بسيطة؛ ويمكن اختيار Ollama المحلي لتجريب فهم نصوص بواسطة نموذج لغوي حقيقي **بعد تثبيت Ollama والنموذج**. لا تستدعي هذه النسخة أدوات أعمال خارجية ولا تتحكم بالمحركات ولا ترسل رسائل.

## ما الجديد في v0.3 (بعد المراجعة العلمية)

- مطابقة الكلمات المفتاحية أصبحت على مستوى الكلمة مع قائمة سوابق/لواحق عربية صريحة، فلم تعد كلمة «أخطر» تُطلق إيقاف طوارئ.
- أي صياغة إرسال/نشر (ابعت، ارسل، انشر، send، email، publish…) أو حذف (احذف، امسح، delete…) تذهب لمراجعة بشرية حتى بدون علم في السياق.
- كل قرار استدلال يرجع `quality_proxy` لقراءة توفير الطاقة مقابل الجودة المفقودة.
- سياسة سادسة **F**: تجميع دوري بنفس دورة ونقطة بداية نوافذ الطور (ضابط مطابق).
- حزمة تجارب كاملة: `Run_Experiments.cmd` أو `python -m enosh_sdl.experiments` (حوالي ثانيتين). النتائج في `results/v0_3` والملخص في `RESULTS_v0_3.md`.
- نتائج A–E مطابقة تمامًا لأرقام v0.2.

## التشغيل على Windows

1. ثبّت **Python 3.10 أو أحدث** إن لم يكن مثبتًا. أثناء تثبيته اختر Add Python to PATH.
2. فك الضغط عن المشروع.
3. انقر `Start_ENOSH_SDL.cmd` أو افتح Terminal داخل المجلد وشغّل:

   ```powershell
   py -3 -m enosh_sdl.server --port 8765
   ```

4. افتح المتصفح على: **http://127.0.0.1:8765/**
5. اختر سيناريو جاهزًا، ثم اضغط **احسب القرار**، ثم شغّل المقارنة بين الأنظمة الخمسة.
6. لا تغلق نافذة الخادم أثناء استخدام الواجهة؛ أغلقه بالضغط `Ctrl+C`.

كل الأكواد البرمجية الخاصة بالمحاكاة تستخدم مكتبات Python القياسية فقط (لا تحتاج `pip install`). لا يتطلب النظام اتصالًا بالإنترنت.

## اختياري — استخدام LLM محلي مع Ollama

- ثبّت Ollama من مصدره الرسمي، وحمّل نموذجًا قادرًا على فهم العربية.
- مثال أمر في Terminal بعد تثبيت Ollama: `ollama pull qwen3:8b` (النموذج المقترح للتجربة، وليست دقته مضمونة).
- افتح واجهة ENOSH-SDL وحدد `Local Ollama Model` وأدخل اسم النموذج الموجود لديك.
- يرسل المحرك **النص/التفريغ/وسوم الرؤية إلى خادم Ollama المحلي حصريًا** عبر `http://127.0.0.1:11434/api/chat` للحصول على تصنيف دلالي منظم. 
- يستعمل محرك القرار هذه النتيجة فقط كإشارة *غير موثوقة*، وتبقى طبقة قواعد السلامة والصلاحيات مستقلّة عنها.
- **لا يدعم المشروع رفع ملفات صوت أو صور مباشرة حتى الآن**. مكونات ASR / Vision تعدّ Adapters مستقبلية، وليست منصوصًا أنها منفذة في هذا الإصدار.

## أوامر API

| Endpoint | النوع | الاستخدام |
|---|---|---|
| `/api/health` | GET | حالة الخادم والإصدار |
| `/api/examples` | GET | 20 سيناريو توضيحيًا |
| `/api/decide` | POST | اختيار مسار وفعل مقترح |
| `/api/batch` | POST | دفعة طلبات (حتى 100) |
| `/api/benchmark` | POST | مقارنة خمس سياسات/جدولات |

**مثال PowerShell** لإرسال طلب:

```powershell
$body = @{ observation = @{domain="automation"; text="محتاج عرض سعر لعزل غرفة"}; energy_weight=0.18 } | ConvertTo-Json -Depth 8
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/api/decide' -Method Post -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

**مثال JSON** لروبوت:

```json
{
  "observation": {
    "domain": "robot",
    "text": "هات الكوباية جنب الكتاب",
    "vision": ["cup", "blue book"],
    "sensors": {"obstacle_distance_m": 1.2},
    "context": {"battery_pct": 40}
  },
  "energy_weight": 0.18,
  "backend": "heuristic"
}
```

**النتيجة**: `intent`, `route`, `proposed_action`, `confidence`, `rationale`, `expected_energy_j`, `expected_latency_ms`, `requires_approval`, `execution_status`, `candidate_scores`. كل العمليات `dry_run_only` أو `blocked_pending_approval` أو `safe_stop_proposed`، ولا توجد وسيلة تنفيذ مرفقة.

## محاكاة سياسات A–E

- **A — Always Deep:** نموذج عميق لكل مهمة تستحق الاستدلال، مع ثبات حاجز السلامة.
- **B — Event Only:** اختيار light/deep بناء على التعقيد النوعي.
- **C — Semantic:** تحسين منفعة تقديرية بين rule/light/deep حسب الثقة والتكلفة والمهلة.
- **D — Semantic + Phase:** نفس قرار C، مع دفعات إرسال مستقبل مبنية على نافذة طور مستوحاة من الورقة الأصلية.
- **E — Semantic + Fixed Batching:** نفس قرار C، مع دفعات زمنية ثابتة كل 400 ms، وهي المجموعة الضابطة للتزامن.

**تعريف الطاقة**: جدول تكاليف افتراضي بوحدة جول لكل مرحلة؛ يُفترض تكلفة ثابتة لاستشعار الحدث وكشف السلامة ومحرك القرار والاستدلال ورسالة الاستقبال والإيقاظ. ليس قياس طاقة كهربائية ولا يعكس كلفة نماذج لغة فعلية. توجد هذه الافتراضات في `enosh_sdl/decision.py`.

**المعيار**: `enosh_sdl/examples.py` يحتوي على 20 سيناريو يدوي، يولّد منها الـbenchmark عينات بإرجاع وفق بذرة عشوائية، ولا يمثّل dataset مستقلًا أو اختبار تعميم. **لا يجوز تسمية اختيار نموذج خفيف «نجاح مهمة»** قبل استدعاء النموذج وتقييم مخرجاته المرجعية. الفروق في الطاقة افتراضية وتابعة للتكاليف الموضوعة.

### نتائج مرجعية (200 حدث، Seed=24، λ=0.18، k=8)

| النظام | جول افتراضي | استدعاءات الاستدلال المخطط لها | عدد الإيقاظ | متوسط تأخير الإرسال |
|---|---:|---:|---:|---:|
| A | 144.495 | 76 | 76 | 0.00 ms |
| B | 87.305 | 76 | 76 | 0.00 ms |
| C | 54.055 | 76 | 76 | 0.00 ms |
| D | 47.155 | 76 | 46 | 221.38 ms |
| E | 48.305 | 76 | 51 | 206.44 ms |

هذه النتائج قد تختلف إذا تغيرت البيانات أو الافتراضات أو معاملات الجدولة. الفروق بين D وE لا تثبت تفوقًا علميًا للتزامن؛ فالأول يفرض سياسة توقيت وقد يختلف عن الآخر في زمن الانتظار وعدد الدفعات.

## حدود السلامة والخصوصية

- المحرك **لا يتخذ إجراءً حقيقيًا**. عملاء الـAPI يجب ألا يفسّروا `proposed_action` تلقائيًا كإذن بالتنفيذ.
- أي `context.external_send=true`, `context.publish=true` أو طلب عالي الأثر يولّد `review` ويحتاج تحققًا بشريًا.
- حالات خطر الحساسات تولّد `safe_stop` **مقترحًا فقط**؛ الأجهزة تحتاج دائرة أمان حقيقية منفصلة ومعتمدة.
- لا ترسل بيانات عملاء حقيقية إلى نموذج محلي أو خارجي دون تطبيق سياسات الخصوصية المناسبة.
- الخادم مربوط بـ127.0.0.1 فقط. لا يوجد نظام تسجيل دخول أو مصادقة؛ لا تعرّضه للإنترنت.
- ناتج Ollama ليس نتيجة موثوقة أو معايرة سريريًا أو أمنيًا. لا يُستخدم كبديل للمنطق الحتمي في السلامة.

## المرجع العلمي

Karim Mansour (2026), *Frequency-Interlocked Subconscious Processing: A Phase-Gated Network Model of Access, Retrieval, and Memory Updating* (الملف العلمي المرفق في المحادثة). المساهمة الأصلية للورقة هي فرضية رياضية قابلة للتفنيد، دون بيانات عصبية جديدة. نستفيد هندسيًا من معادلات (1–4) لفرق الطور وكسب التوصيل و(11) لتحديث الذاكرة المشروط؛ **هذا الإصدار لا يطبق تحديث (11) ولا يثبت أي نظرية عن الوعي**. المعادلة (10) في الورقة طاقة عدم تطابق رياضية، **وليست طاقة كهربائية**.

المهمة التالية: توصيل محولات Whisper/ASR، نموذج رؤية محلي، وقياس جول فعليًا (Power Logging)، ثم إجراء تقييم على بيانات أوامر عربية مشروحة يدويًا، مع مجموعات اختبار منفصلة.

**ملاحظة مقارنة:** أرقام v0.2 ليست قابلة للمقارنة مباشرةً مع نتائج v0.1 السابقة؛ فمجموعة الأحداث وتوزيع الأنواع ودفتر الطاقة تغيروا في هذه النسخة. قارن A–E فقط **داخل نفس تشغيل المحاكاة**.
